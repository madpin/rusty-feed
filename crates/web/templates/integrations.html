How each box works

Rusty Feed delivers each event as an authenticated JSON POST to your endpoint. Slack, Discord, Telegram, and ntfy receive a body those services accept directly; every other destination receives Rusty Feed's generic envelope, so point it at a URL that understands that JSON (the service's own webhook or a small relay/automation).

Name
A label for you; it never leaves Rusty Feed.
Provider
Selects the payload shape and shows the endpoint/credential hints above. It does not change where the request goes — that is entirely the endpoint you enter.
HTTPS endpoint
The exact URL Rusty Feed POSTs to. Must be HTTPS and publicly reachable (private/loopback addresses are blocked); redirects are not followed.
Credential mode & Credential
Bearer sends Authorization: Bearer <token>. Basic takes username:password. HMAC-SHA256 signs the body and adds x-rusty-feed-signature: sha256=<hex>. None sends no auth (use when the secret is already in the URL). Credentials are encrypted at rest and never displayed again.
Tags
Comma-separated labels included in the payload and available to the template as the tags token.
Retry attempts
How many times a failed delivery is retried with backoff before it is marked dead (1–12).
Rate limit/minute
Caps deliveries per minute to this destination; anything over the limit is retried later.
Message template
Rendered into the payload's message field. Tokens (each wrapped in double braces): title, url, author, excerpt, event, tags.
Events
Which actions trigger a delivery: explicit send, bookmark, new feed entries, or summary ready.
Default destination
Pre-selected when you use “Send to…” on an article.

Every request also carries x-rusty-feed-event-type and x-rusty-feed-payload-version headers.
