# Miniflux Feature-Parity Tracker

This is the living delivery checklist for Rusty Feed parity with the
[official Miniflux feature inventory](https://miniflux.app/features.html), last
reviewed on **2026-09-01**. It includes every capability on that page, including
items that were not in the initial summary (themes, minimal UI, bundled assets,
Twelve-Factor operation, and packaged distributions).

Parity means matching the useful product outcome, not copying Miniflux's Go
implementation. Rusty Feed remains Rust-native and keeps its defining invariant:
**content is shared; state is personal**. Feed download, extraction, media
fetching, embedding, and summarization must stay O(1) for N subscribers.

## How to maintain this document

Update this file in the same change that develops or materially changes a
listed capability.

| Marker | Meaning |
|---|---|
| `✅` | Complete, exposed to the intended user/admin, documented, and covered by proportionate automated tests |
| `🟡` | Partially implemented; the row states the missing parity work |
| `🚧` | In progress on the current branch |
| `⬜` | Accepted requirement, not implemented yet |
| `⚠️` | Product/security design decision required before implementation |

When a row changes:

1. Change it to `🚧` before implementation starts.
2. Add links or paths to its implementation, tests, and operational docs in the
   row's evidence note.
3. Mark it `✅` only after the customization and acceptance conditions are met.
4. Update the baseline totals and `Last reviewed` date.
5. Record newly discovered risks in `docs/FINDINGS.md`.

## Customization contract

Every parity feature must expose the controls that are useful at its natural
scope. The scope codes used below are:

- **I** — instance default and admin-enforced bounds/policy.
- **U** — per-user preference.
- **C** — personal category/folder override.
- **S** — personal subscription override.
- **F** — shared feed/source acquisition setting, administered once.
- **X** — named integration/credential profile.

Unless a requirement explicitly needs another rule, effective configuration is
resolved as `S → C → U → I → safe built-in default`. Shared acquisition uses the
aggregate subscriber intent plus `F/I` safety controls; it never fetches once
per user. The longest requested content lifetime wins, including infinite.

Customization is complete only when:

- settings have a discoverable UI and an API representation where applicable;
- defaults, allowed values, validation, reset/inherit behavior, and effective
  value are clear;
- secrets are encrypted and masked; changes are auditable without logging secret
  material;
- import/export and backup behavior is documented;
- inaccessible or unsafe combinations fail closed with an actionable message;
- configuration works without making shared work O(N);
- tests cover precedence, tenant isolation, validation, and the safe default.

“Highly customizable” does not mean that a user can disable instance safety
boundaries. SSRF defenses, content sanitization, secret handling, and CSP remain
mandatory. Risky capabilities are opt-in and admin-bounded.

## Beyond-parity product bar

Miniflux's inventory is the compatibility floor. A Rusty Feed capability is not
finished merely because a checkbox exists: common publisher intent must survive
normalization, privacy choices must be reversible in context, failure must retain
a useful fallback, interaction state must be announced accessibly, and shared
work must remain observable and O(1). Evidence notes call out these improvements
where Rusty Feed deliberately exceeds the baseline rather than silently widening
scope.

## Remaining delivery order

Shared foundations and every security-design decision are implemented. The two
partial rows should finish in this order:

1. **Complete localization:** extract the remaining feature/admin/validation/
   notification/accessibility strings, provide all 20 catalogs and translator
   validation, then run per-locale RTL/LTR browser snapshots.
2. **Turnkey provider contracts:** retain the generic durable delivery port, but
   add exact endpoint/auth/body/response fixtures for each advertised hosted
   provider. Remove or label any provider whose current contract cannot be
   tested without overstating compatibility.

## Definition of parity

Rusty Feed reaches Miniflux feature parity when all 67 rows are `✅` and the
following cross-cutting gates pass. All former security-decision rows now have
an accepted, bounded design and evidence:

- multi-user dedup/invariant integration tests;
- accessibility and keyboard/touch-equivalence tests;
- desktop/tablet/mobile browser flows;
- SSRF, sanitizer, CSP, secret, OAuth/OIDC/WebAuthn, and tenant-isolation tests;
- import/export round trips and API conformance suites;
- upgrade/migration, backup/restore, worker-failure, and graceful-degradation
  exercises;
- documented configuration reference with defaults, bounds, scopes, and examples.
