# Rusty Feed — Findings, Smells & Risks (living document)

**Purpose:** a single running log of code smells, potential problems, bugs, and risks discovered while analyzing the reference `neureed` implementation and while building Rusty Feed. Each entry has an ID, severity, status, and a proposed action.

**Process:**
- Add an entry the moment something questionable is found — don't rely on memory.
- Reference the entry ID in commits/PRs that address it (e.g., `fixes FND-003`).
- This document is **revisited and triaged at the end of Phase 1 (analysis/design)** and again at each milestone.
- Keep it honest: include risks in *our own* design, not just the reference's.

**Severity:** `critical` (data loss / security / corruption) · `high` (wrong behavior / perf cliff) · `medium` (smell / maintainability / minor bug) · `low` (nit / cosmetic).
**Status:** `open` · `planned` (has a design decision) · `in-progress` · `resolved` · `wontfix` · `monitor`.

## A. Reference implementation (`neureed`) — carried into design

These were found by reading the reference. Rusty Feed's design already addresses most (cross-referenced to PRD §9 and the Architecture doc). Tracked here so nothing is silently forgotten during implementation.

| ID | Sev | Status | Finding | Action / where addressed |
|---|---|---|---|---|
| FND-001 | high | resolved (M6) | **Conditional GET implemented but not wired.** `feed-parser` supports `If-None-Match`/`If-Modified-Since` + 304, but `feed-refresh-service` calls `parseFeedUrl(url)` with no options and never stores `etag`/`lastModified` (explicit TODO). Every refresh is a full GET. | **Resolved:** `FetchFeedAgent` persists and re-sends `etag`/`last_modified`; a 304 short-circuits the refresh (`crates/feeds/src/lib.rs`). |
| FND-002 | critical | resolved (M9) | **Mixed-dimension/space embedding corruption.** (original app) padded 384→1536 and mixed providers in one column. | Fixed `vector(384)` column + **one model per instance**; OpenAI requests `dimensions=384` (no pad/truncate); every vector stores its `model` and **search/related queries filter by the current model**, so switching providers never compares across spaces. PRD FR-EMB-3; ARCH §13. |
| FND-121 | medium | resolved (M9) | **The local provider was a deterministic feature-hashing placeholder, so default “semantic” search was lexical.** | `fastembed` 6 runs BAAI BGE-small-en-v1.5 locally with lazy, bounded blocking inference. `MODEL_CACHE_DIR` is persistent; `fetch-model` verifies an online/offline seed; aliases canonicalize to one durable name; startup rejects a different durable space until the explicit confirmed reindex flow is used. The hash implementation remains explicit test/emergency fallback only. |
| FND-003 | high | resolved (M12) | **Cost tracking is in-memory only** (original app). | Durable `cost_ledger` table + repo (per user/provider/model/kind/day) written by the summarize path; admin aggregates at `/admin/costs`. Embedding-cost recording will reuse the same ledger. PRD FR-LLM-4; ARCH §14. |
| FND-004 | high | resolved (M12) | **Two incompatible crypto schemes** (original app). | One unified AEAD in `core::crypto`: XChaCha20-Poly1305 with an HKDF-SHA256-derived key from `ENCRYPTION_SECRET`, envelope `base64(version‖nonce‖ct)` with the key version authenticated (AAD) for future rotation (FND-110). Round-trip/tamper/wrong-key tested. Per-user/admin key storage can use this primitive; authenticated feed-cookie extraction is deliberately unsupported (public pages only). PRD §9.4; ARCH §14/§21. |
| FND-005 | medium | resolved (M13) | **`preserveStarred` is a no-op.** Cleanup accepts `preserveStarred: true` but there is no starred/bookmark model, so nothing is preserved. | Shared retention now checks the real personal `bookmarks` table and preserves an article when any user has saved it. Zero-day retention means infinite; finite cleanup is configuration-owned and never removes RSS merely because a public-page copy expires. PRD FR-JOB-3/4; ARCH §6/§11.6. |
| FND-006 | critical | resolved (M6) | **SSRF gaps beyond feed creation.** Only `createFeed` validated URLs; extraction/robots fetches only checked scheme — no private-IP blocking, no redirect re-validation (DNS-rebinding). | Done in `rusty-feed-feeds::SafeFetchClient`: a custom reqwest DNS resolver rejects any host resolving to a non-public address (covers every redirect hop), plus IP-literal validation before connect. Extraction (M8) will reuse the same client. A `new_allow_private` variant exists for tests / explicitly-trusted intranet feeds. PRD FR-EXTRACT-5; ARCH §12. |
| FND-007 | medium | resolved (M6/M7) | **Job wiring is inconsistent.** (original app) crons defined-but-never-called; ad-hoc locks/run tracking. | `rusty-feed-agents` provides one runtime: durable `job_queue` (SKIP LOCKED), a scheduler enqueuing a deduped `feed_refresh`, singleton `agent_locks` leases, and `agent_runs` records. Agents register by kind; feed refresh is O(1) per shared feed (deduped `fetch_feed`). Embeddings/pattern-decay agents will slot into the same runtime in later milestones. PRD FR-JOB-1/2; ARCH §8. |
| FND-120 | low | resolved (M8) | **The public-page extractor had no headless-browser tier and the Compose Chrome command duplicated the image's private CDP port.** | Chromiumoxide now connects to the corrected remote-CDP service with bounded concurrency/timeouts. It receives only the HTML already fetched by `SafeFetchClient`, executes under a no-network CSP, and degrades to local extraction. The real-service integration test verifies inline application rendering without giving Chrome an SSRF bypass. |
| FND-119 | low | resolved (M7) | **Cron strings and the transactional outbox existed but the runtime ignored both.** | A validated five-field UTC cron matcher drives due scans once per minute. Feed refresh publishes transactionally to the durable outbox; a continuously running `SKIP LOCKED` dispatcher converts allowlisted events into deduplicated queue work even when cron is disabled. Rollback/commit/dedup tests cover the boundary. |
| FND-008 | medium | planned | **`KEYS`-based cache invalidation** (`cacheDeletePattern` uses `KEYS pattern`) is O(N) and blocks Redis at scale. | Use `SCAN` + tag/prefix invalidation. PRD §9.8; ARCH §10. |
| FND-009 | medium | resolved (M13) | **Cleanup ages by `createdAt`, not `publishedAt`.** Surprising for backfilled feeds (old articles just ingested get deleted immediately or kept wrongly). | `RETENTION_AGE_BASIS` explicitly chooses publisher time (default, with ingestion fallback) or ingestion time; `ARTICLE_RETENTION_DAYS=0` is infinite and finite deletion preserves every bookmarked row. PRD §9.9; ARCH §11.6. |
| FND-010 | high | planned | **System (scheduled) refresh passes no `userId`.** Result: no summaries generated on scheduled refresh, and embeddings always use the system/default (local) provider regardless of user config. Per-user enrichment only happens on manual user-scoped refresh. | In Rusty Feed, enrichment is decoupled from the fetch and keyed by shared article (agents), not by user. Summaries are on-demand/optional-auto (admin-gated); embeddings use the single instance model. ARCH §7.3/§8. |
| FND-011 | medium | monitor | **URL dedup is global but GUID/hash dedup is feed-scoped.** An article URL present in two feeds collapses to one row owned by whichever feed inserted first; that article then "belongs" to a feed the other subscriber may not see as the source. | Preserve reference behavior (global URL uniqueness) but verify UX around "source feed" attribution. Consider an article↔feed association table if this proves confusing. Revisit. |
| FND-012 | low | monitor | **Near-duplicate detection defined but unused.** `calculateSimilarity`/`areNearDuplicates` (Jaccard, 0.8) exist but aren't called in the refresh path. | Decide whether to implement near-dup collapsing in Rusty Feed or drop it. Low priority. |
| FND-013 | medium | resolved (M12) | **Summary cost pricing table missing `gpt-4o-mini`.** | `llm::pricing` includes gpt-4o-mini/4o/4.1-mini + embedding models in micro-USD; unknown/local models cost 0 (tested). ARCH §14. |
| FND-014 | low | monitor | **Reference docs (CLAUDE.md) disagree with code** in several places (cost tracking "Redis" but it's in-memory; `feedMetadata` TTL "5 min" but code is 1h; summary TTL "1h" vs code 7d; search threshold 0.7 vs service 0.5). | Rusty Feed docs use the **code-verified** values (ARCH §10/§11). Note for anyone cross-referencing the reference. |
| FND-015 | medium | planned | **Robots.txt path allow/deny is simplified** in the reference (`allowed: true` always; only crawl-delay is honored). | Decide Rusty Feed policy: at minimum honor crawl-delay; optionally honor Disallow for extraction. Document the choice. |

## B. Rusty Feed design/implementation — risks to watch

Risks introduced (or not yet closed) by our own choices. Revisit at each milestone.

| ID | Sev | Status | Finding | Action / mitigation |
|---|---|---|---|---|
| FND-101 | high | monitor | **Postgres-backed queue throughput ceiling.** The custom `SKIP LOCKED` queue is simple and durable but caps throughput versus a dedicated broker. Fine for target scale (1–500 users), but verify against the ≥200 feeds/min + ≥1000 saved-search matches/min targets. | Benchmark before v1 (ARCH §20). If needed, move hot lanes to a dedicated broker while retaining PostgreSQL run/audit state and transactional event delivery. |
| FND-102 | medium | monitor | **Server-rendered UI versus rich SPA interactions.** Resizing, drag/drop, live status, theme changes, and offline data were SPA-native in the reference and require careful progressive behavior. | Dependency-free JavaScript now covers accessible reader resizing, inline/side-panel modes, drag-to-folder, dialogs, live summary/queue status, install state, and no-JS fallbacks. Live system-theme changes, the complete mobile/a11y matrix, and any explicitly designed offline article store remain backlog. PRD §2.2 keeps pixel identity out of scope. |
| FND-103 | high | monitor | **Model download on first run = network dependency + startup latency.** First run needs egress to fetch ONNX weights; air-gapped installs will fail without a pre-seeded `MODEL_CACHE_DIR`. | Document offline seeding; provide a `rusty-feed-cli fetch-model` command; clear error if weights missing and network blocked. |
| FND-104 | medium | monitor | **Chromium resource use.** Headless Chromium is memory-hungry and can undermine the <300 MB loaded-RSS target if run in-process. | Run Chromium as a **separate** compose service (pooled, capped); app talks CDP over the network. Off by default is not an option (Full infra), but keep concurrency bounded. |
| FND-105 | high | planned | **GReader is a de-facto, unversioned spec.** Real clients rely on undocumented quirks; partial implementations cause subtle client breakage. | Scope to the Miniflux/FreshRSS-supported subset; add integration tests that replay real client request sequences; document supported endpoints. ARCH §9.1. |
| FND-106 | medium | monitor | **Embedding model change is disruptive** (full re-embed). If an admin swaps `EMBEDDING_MODEL`, search is degraded until backfill completes. | Make it an explicit, guarded admin flow with progress; keep old table until backfill done, then swap. ARCH §13.1. |
| FND-107 | medium | resolved | **`sqlx` compile-time query checks need a DB or offline cache** (`SQLX_OFFLINE` + `.sqlx/`). CI without a DB would fail unless offline metadata is committed. | **Resolved (M2):** use **runtime** `sqlx::query`/`query_as` (not the `query!` macros). Builds stay hermetic (no DB, no `.sqlx/`); SQL correctness is covered by integration tests against a real Postgres (CI runs a pgvector service). |
| FND-111 | low | planned | **Preferences stored as a JSONB blob** (`user_preferences.preferences`) rather than the 30+ typed columns the Architecture describes. | Deliberate: a typed Rust struct (serde) will define the shape in M5 and (de)serialize to JSONB, avoiding migration churn. Revisit if we need SQL-level querying of individual preferences. |
| FND-112 | medium | monitor | **`article_embeddings.embedding` dimension is hardcoded to `vector(384)`** in the initial migration (the default local BGE-small model). An instance configured for OpenAI (1536) needs a different dimension. | Aligns with the "one model per instance; model change = explicit re-embed" policy (ARCH §13.1). M9 adds a guarded re-dimension/backfill flow; document the OpenAI setup path in `docs/MIGRATION.md`. |
| FND-108 | medium | monitor | **Content sanitization vs. fidelity.** Aggressive `ammonia` allow-lists can strip legitimate embeds (iframes for video, etc.); too permissive risks XSS. | Keep stored feed content iframe-free. A separately generated, opt-in live publisher frame has an isolated contract (FND-134); extend the feed-content allow-list only after source-specific safety review. |
| FND-109 | low | open | **UUIDv7 vs. reference cuid/nanoid IDs.** Migration must map or preserve old string IDs; mixing formats needs care in FKs. | Decide in `docs/MIGRATION.md`: keep old IDs as `text` for migrated rows, UUIDv7 for new; or remap via translation tables. |
| FND-110 | medium | monitor | **Two crypto/secret classes at rest** (API keys, feed cookies) all hinge on one `ENCRYPTION_SECRET`. Losing/rotating it invalidates all secrets. | Document rotation procedure; support re-encrypt-on-read with a versioned key id (AEAD associated data includes a key version). |
| FND-114 | low | resolved (M3) | **Cross-instance L1 entries could remain stale after another instance changed Redis L2.** Local `delete`/`delete_prefix` were correct, but sibling moka caches previously stayed warm until their per-entry TTL. Multiple Rusty Feed installations could also collide when sharing Redis because L2 keys were unnamespaced. | Redis-backed instances now use validated installation namespaces for both L2 keys and a versioned Pub/Sub channel. Exact and prefix invalidations carry sender IDs; sibling instances evict matching L1 entries. Initial subscription is required before L2 is enabled, and a disconnect clears then bypasses L1 until bounded reconnection succeeds. Two-instance Redis tests cover updates, deletes, prefixes, and namespace isolation; invalid Redis still degrades to functional L1-only caching. Existing unnamespaced entries are disposable and expire naturally. |
| FND-118 | low | monitor | **Curated hand-written CSS instead of the originally proposed Tailwind pipeline (M5).** To avoid a Node/standalone-binary build dependency, Rusty Feed ships a compact design-system stylesheet (CSS variables, components, light/dark/system) plus dependency-free progressive `app.js`, both embedded with rust-embed. | README, Architecture, and AGENTS now describe the shipped stack. Revisit Tailwind only if the design system outgrows the curated CSS; do not add a frontend build dependency without measuring the trade-off. |
| FND-117 | low | planned | **OAuth implemented directly over `reqwest` instead of the `oauth2` crate (M4b).** Authorization-code flow with PKCE (S256) + `state` CSRF, provider profile fetched from userinfo; supports Google, GitHub, and a generic OIDC provider. | Deliberate: TLS control (rustls, no OpenSSL) and hermetic testability (wiremock). Security-sensitive — covered by integration tests (happy path + state-mismatch rejection). Reconsider the crate if we need broader OIDC features (discovery, id_token validation). Docs updated (ARCH §15). |
| FND-116 | low | planned | **Custom session scheme instead of `tower-sessions` (M4a).** The Architecture named `tower-sessions` + a sqlx store; we implemented a small DB-backed scheme (opaque token in an HTTP-only cookie; SHA-256 hash stored in `sessions`) to avoid session-library version churn and keep full control. | Deliberate. Satisfies FR-AUTH-3 (server-side sessions in Postgres). Revisit if we need session features (rolling stores, layered middleware) that the library provides. Docs updated (ARCH §15). |
| FND-115 | medium | resolved (M12/UI) | **Compose commands did not load/forward the root `.env`.** Because the Compose file is under `docker/`, commands without an explicit env file silently ignored root-level host-port overrides and secrets; even with `--env-file`, values were only available for Compose interpolation rather than automatically injected into `app`. | Standardized commands on `docker compose --env-file .env -f docker/compose.yaml …`, then added `app.env_file: ../.env` so runtime configuration (`BASE_URL`, OAuth, AI, cache, feed policy, etc.) reaches the container while Compose-only internal DB/Redis URLs stay explicit. Config validation verified with `docker compose … config --quiet`. |
| FND-122 | high | resolved (UI) | **JS-enhanced article actions posted `multipart/form-data` to Axum `Form` handlers, then attempted a strict-mode `arguments.callee` fallback.** In browsers this produced a 415 before the handler and the fallback threw, making read/save/feedback controls appear broken; repeated feedback could also over-train patterns. | Actions now convert `FormData` to `URLSearchParams` (browser `application/x-www-form-urlencoded`), disable while pending, announce success/failure, and never invoke the broken fallback. Read/bookmark state is synchronized from panel responses; mark-all reloads the current list; feedback displays its durable selection and applies only the value delta, so retrying the same choice is idempotent. |
| FND-123 | medium | resolved (UI) | **OpenAI base URL configuration could form `/v1/v1/...`.** The example used a conventional `/v1` suffix while both clients appended `/v1` unconditionally. | Embedding and LLM clients normalize root and `/v1` base URLs to exactly one version segment, with unit tests for both forms. The generic OAuth example now uses the actual `OAUTH_AUTH_URL` variable. |
| FND-124 | high | resolved (feed policy) | **An RSS refresh could overwrite extracted full text.** Feed and effective article bodies shared one field, so an unchanged-page re-ingest could replace extraction output while its status remained successful; web refresh also bypassed the shared queue/policy path. | Migration 0004 separates sanitized `feed_content`/fallback hash from effective content, adds revision guards, and invalidates stale summary/vector state on effective changes. New extraction writes are version-checked; search filters vectors by matching revision. UI refreshes queue the same deduplicated `fetch_feed` work as the scheduler. |
| FND-125 | medium | resolved (feed policy) | **Feed-source configuration was invisible and ambiguous.** The existing `extraction_settings` JSON had only an internal `enabled` flag; users could not choose RSS versus public page extraction, and known paywalled publishers could trigger futile requests. | A typed shared policy now exposes RSS content or anonymous public-page extraction with RSS fallback (robots policy, delay, and selector configurable). Publisher restrictions never trigger credential use or bypass attempts; admin-only policy editing preserves O(1) shared acquisition. |
| FND-126 | medium | resolved (catalog/admin) | **No safe discovery or complete administration surface.** Users had to know feed URLs, while the only admin UI was a cost table. | Migrations 0005/0006/0012/0015/0022 add an editorial catalog separate from shared feeds, now containing 200 verified starter sources, country/category/language facets, automatic facet filtering, derived source statistics, and idempotent multi-select subscription. An admin dashboard adds guarded user roles, shared-feed inspection/source policy links, catalog publishing/reordering, safe operations activity, and costs. |
| FND-127 | medium | resolved (shortcuts) | **Power-reader actions were pointer/form-only.** There was no configurable, persisted keyboard workflow and single-key handling could have conflicted with text entry or assistive/browser controls. | Per-user preferences now hold a validated, conflict-free shortcut map with a capture/reset UI. The dispatcher reuses existing links/forms, supports article/feed navigation plus save/unread, and declines events from editable controls, media, dialogs, account menus, IMEs, repeats, and Ctrl/Alt/Meta combinations. |
| FND-128 | high | resolved (safe fetch/icons) | **A redirect could move an otherwise-valid request to a private IP literal, bypassing hostname-only DNS filtering.** Environment proxy discovery could also sidestep the intended direct resolution policy. | SafeFetch now validates every redirect target for scheme, credentials, and private IP literals, retains the bounded redirect limit, and disables implicit system proxies. Feed icon downloads use this same client, are time/size bounded, raster-signature checked, and never fail article ingestion. |
| FND-129 | medium | resolved (organization) | **Personal category/tag tables existed but feeds could not be organized or used to scope the Library.** | Nested personal folders, one current folder per feed, normalized multi-valued tags, descendant-aware Library filters, filtered mark-all-read, a searchable organizer, and folder-first sidebar navigation now use only personal rows. Shared feeds/articles/jobs remain O(1). |
| FND-130 | low | monitor | **The base schema foreign keys do not prove that a category parent or a feed-category link belongs to the same user, and legacy data can contain multiple folder links.** | Current repository writes, including OPML import, validate category ownership inside a transaction and replace membership with one selected folder; reader filters are user-scoped. Safe structured feed-error records are resolved on recovery; the no-store operations view exposes only classes, status, counters, and allowlisted numeric stats. Worker persistence uses a generic safe failure message. |
| FND-132 | medium | resolved (reader links) | **Standard RSS 2 `<comments>` links, including Hacker News discussion URLs, were discarded by the parser, leaving readers without a path to the conversation.** | A bounded XML sidecar retains safe RSS comments URLs separately from the canonical article URL. Comments-only updates preserve extraction and summary state; reader and side-panel views offer an `Open comments` link beside the original article. |

| FND-138 | high | resolved (content ownership) | **A shared admin-owned RSS/public-page mode prevented subscribers from owning their content choice, replaced the RSS body in the effective reader path, and had no finite/infinite lifetime or access-time recovery contract.** | RSS and public-page bodies are now retained separately. `user_feeds.settings` owns each subscriber's source and lifetime; requests reduce to one shared extraction with longest/infinite lifetime semantics. | FND-139 | high | resolved (reliable Live View) | **Direct publisher iframes fail whenever a site sends `X-Frame-Options` or restrictive `frame-ancestors`; relative resources and mixed HTTP assets also made successful frames visually inconsistent. | FND-145 | medium | resolved (referrer isolation) | **External-link privacy depended on individually-authored template attributes, and sanitized publisher links had no explicit `referrerpolicy`; new surfaces could silently regress.** | The outer router now mandates `Referrer-Policy: no-referrer` for every response.
