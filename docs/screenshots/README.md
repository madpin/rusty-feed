# Screenshots

Product screenshots used by the top-level [`README.md`](../../README.md). They are
generated by [`scripts/capture-screenshots.mjs`](../../scripts/capture-screenshots.mjs)
so they can be refreshed whenever the UI changes.

| File | Page |
|---|---|
| `library.png` | Reading list with per-feed unread counts and the in-place reading panel |
| `discover.png` | Discovery magazine with the filter-aware "select all" |
| `article.png` | Standalone article reader |
| `feeds.png` | Feed management and the bulk-action toolbar |
| `ai-providers.png` | Managed AI providers (incl. the environment default) |
| `integrations.png` | Integrations & webhooks with per-destination guidance |
| `admin-overview.png` | Admin instance overview (stat cards + storage/memory) |
| `admin-feeds.png` | Admin shared feeds (full-width table with stats, filters, pagination) |
| `admin-logs.png` | Admin queue & logs (per-job target column names the feed/article) |

## Regenerating

1. Start the stack and a server (a populated database makes the best screenshots):

   ```bash
   docker compose --env-file .env -f docker/compose.yaml up -d postgres redis chromium
   BIND_ADDR=127.0.0.1:8088 \
   DATABASE_URL=postgres://rusty_feed:rusty_feed@localhost:5435/rusty_feed \
   REDIS_URL=redis://localhost:6379 \
   SESSION_SECRET=$(openssl rand -base64 48) \
   ENCRYPTION_SECRET=$(openssl rand -base64 48) \
   RUN_EMBEDDED_WORKER=false \
   cargo run -p rusty-feed-server
   ```

2. Capture (installs the Playwright Chromium browser on first use):

   ```bash
   npm ci
   npx playwright install chromium
   node scripts/capture-screenshots.mjs
   ```

The script logs in (or registers) a showcase account, subscribes it to the
discovery magazine so the library is populated, and writes the PNGs here.

To include the admin screenshots, promote the showcase account once, then re-run:

```sql
UPDATE users SET role = 'admin' WHERE email = 'showcase@rusty-feed.local';
```

Environment overrides: `SHOT_BASE_URL`, `SHOT_OUT_DIR`, `SHOT_EMAIL`, `SHOT_PASSWORD`.

> Note: the admin "Process memory (RSS)" figure reads `/proc` and shows
> "Unavailable on this platform" when captured on macOS; on Linux/containers it
> shows the live resident set size.
